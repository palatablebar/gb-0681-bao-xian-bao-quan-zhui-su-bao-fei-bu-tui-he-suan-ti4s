# 保费补退定义

每份保单有且仅有一条issue基线。change按effective、责任、version选版；同生效日同版本矛盾拒绝。cancel必须引用同保单的change，取消整份变更，不按录入顺序覆盖。区间为[start,end)。年度保费按所在自然年365或366日拆分，跨年强制切段。先求每段精确保费，再最大余额法分配到分，使段合计等于保单总额。paid为已收金额，总应收减已收为补退额，正数补缴、负数退费。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。

## 重复送达与批次身份

同一批保全流水可能从柜面、线上等多个渠道先后到达。逐个字节不同不等于内容不同：编码（UTF-8 BOM/UTF-8/GB18030）、行序、列序、文件名、千分位与全角数字都只是送达形态。批次身份按“逻辑内容”计算：

1. 按通用采信约定解码并用 csv 解析逻辑记录；
2. 文本按 NFC 归一、统一换行并去首尾空白；
3. 数值列按 NFKC、去千分位后用 Decimal 归一，日期列归一到 ISO；
4. 行按多重集排序、列按表头名排序后哈希，再并入参数与规则版本。

因此同一内容重复送达归并为同一批次，只有一个核算结果与一个签审版本；改一个金额、增删行、增删空行或重复表头都会得到不同身份，不做静默归并。每次到达都单独登记接收台账：渠道、文件名、服务器接收时间、原始字节 sha256、编码、原文与去向，永不覆盖前一次接收。

接收去向：首次到达为“采用”；未签审批次收到同内容为“待辨认”，由复核员辨认后记为“归并”或“复用签审”；已签审批次收到同内容直接“复用签审”并引用签审版本；表头/宽度/空态等无法采信的送达为“拒收”并保留原因码与原文。归并与复用不新增核算结果，不推进签审版本。存在待辨认接收时结案标记为待复核。
